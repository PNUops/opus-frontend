## 시각적 판단과 보완

1440·768·390px에서 인증 화면 기본·최초 안내를 직접 검토했다. 로그인은 제목→레이블/입력→주요 액션→보조 액션 순서가 명확해졌다. 가입은 이름/학번, 이메일 인증, 비밀번호 그룹의 간격을 정리하고 48px 파란 주요 버튼으로 중요도를 드러냈다. 화면 높이는 auth 경로에 한해 header/body/footer를 기준으로 잡아 기존 공통 컨테이너의 누적 빈 공간을 제거했다.

처음 캡처에서 전송 중 스피너와 문구가 떨어져 보여 아이콘 영역을 제한하고 재촬영했다. 오류 문장의 한글 어절을 유지하고 기존 `destructive` 토큰으로 작은 오류·타이머 텍스트의 대비를 개선했다. 실제 계산된 색상 `rgb(231, 0, 11)`과 흰 배경 대비는 약 4.77:1이다. 이는 해당 요소의 측정이며 전체 사이트의 접근성 인증을 뜻하지 않는다.

최초 안내는 모바일 양쪽 16px 이상 여백을 유지한다. 확인 버튼이 있는 안내에 Tooltip을 쓰면 숨긴 설명에도 버튼이 복제되고 배경 입력으로 Tab이 이동해, 기존 Popover의 modal 동작으로 변경했다. 한 개의 확인 버튼, 내부 회원가입 링크, 포커스 이동과 Escape를 검토했다. 확인/가입 이동은 기존 확인 값을 저장하고 Escape는 현재 안내만 닫는다.

## 상태 검토에서 발견하고 수정한 문제

기본 공개 화면 13장 외 인증 상태 12장과 이메일 변경·네트워크 실패 상태를 추가 검토했다. 한글 폰트가 로드된 캡처에서 가로 넘침은 없었다.

- 빠른 두 번 클릭이 렌더링 전 중복 인증 요청을 보냈다. 요청 시작 시 동기 잠금을 잡고 완료/실패 때 해제한다. 대기 상태는 TanStack Query의 상태로 표현한다.
- 요청 중 이메일을 바꾸면 이전 주소의 응답이 새 주소를 인증한 것처럼 잠갔다. 요청 주소와 최신 주소가 같은 경우만 결과를 반영한다. 주소 변경 시 발송·코드·타이머 상태를 초기화한다.
- 응답이 없는 네트워크 오류가 예외를 발생시켰다. 기존 공통 오류 함수로 사용자 메시지를 처리하고 재시도를 허용한다.
- 실패 뒤 재시도의 30초 제한에 이전 타이머가 영향을 주지 않도록 취소·정리한다. 가상시간의 실패 t0→재시도 t10→t30 차단→t40 허용을 확인했다.
- 인증 성공 후 남던 이전 오류 문구를 제거한다. 비밀번호 표시 버튼에는 이름·누름 상태와 auth에서만 44px 터치 영역을 제공한다.

레이블/오류 연결, 인증 전 가입 차단, 인증코드 실패·완료, 로그인/가입 대기·서버 오류, 안내 확인 유지·Escape·키보드 이동을 검토했다. 공통 토스트의 긴 한글·대비 문제는 별도 #333에서 다룬다.

## 설계 근거와 범위

Renewal SCREENS `14:6`·ARCHIVE `14:11`에서 일반 인증 화면의 최종 node는 확인되지 않았다. [Button 14:73](https://www.figma.com/design/HbyxwchvTkzD4pbtdjCHkg/OPUS-Renewal?node-id=14-73), [TextField 687:3271](https://www.figma.com/design/HbyxwchvTkzD4pbtdjCHkg/OPUS-Renewal?node-id=687-3271), 기존 OPUS 화면과 토큰을 함께 참고했다. 관리자 초대 로그인은 일반 인증 화면으로 적용하지 않았다.

AuthLayout과 AuthField는 인증 화면의 간격·레이블·도움말·오류 표현만 맡는다. 기존 폼 상태 hook, DTO, API와 서버 검증 정책을 유지한다. MainLayout/Footer의 높이 규칙은 signin/signup(후행 slash 포함)에만 적용한다. 공유 PasswordInput의 버튼 배치는 기존 사용처에서 유지하고 auth에만 선택적으로 큰 터치 영역을 적용한다.

10/8 회의의 학생 가입 필수 `memberType` 계약은 독립 #315/#318이며 이 UI 브랜치에 중복 구현하지 않았다. 실제 서버 가입에는 해당 계약 수정이 필요하다. 오류 원본 로그 제거는 별도 #316/#317이다. 10/12의 졸업과제 정책이나 직원 가입 정책을 이 화면에서 임의로 확정하지 않았다. OAuth 제공자 이동, 운영 API·이메일 배달, 계정 관리 화면 전체와 모든 보조기기는 이번 검증 범위에 포함되지 않는다.

#314는 아직 develop에 미병합이다. 준비된 기존 QA checkout의 `VISUAL_QA_BASE_URL`로 독립 제품 브랜치를 검사했으며, 이 브랜치에 QA 환경을 복제하지 않았다.
